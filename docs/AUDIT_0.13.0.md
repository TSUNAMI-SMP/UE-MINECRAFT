# 0.13.0 追加調査と検証記録

利用者から就寝中の追加エラー調査・修正と、Minecraft原作への改善を依頼され、0.12.4を基準に調査しました。元のプロジェクトと旧版の配布・ブランチは保持し、新しい0.13.0として配布します。

## 確認して修正した問題

| 問題 | 修正と確認方法 |
| --- | --- |
| アイテム用マスターが生成しない頂点光パラメーターを必須とし、アイテム取り込みが停止 | 地形用とアイテム用の必須パラメーターを分け、実際の生成グラフを厳格なAPI代替へ接続する回帰検証 |
| 天体UVが存在しないVectorParameter出力 `RG` を使用 | RGBからComponentMaskでR/Gを抽出。無効なピンを拒否する検証で太陽・月のUV接続を確認 |
| 素材取り込みの後半で失敗すると、既存パレットの内容やReceiver割当が変更されたまま | ブロック／モデル／アトラス／アイテム／音の旧マップと割当を復元。保存失敗を挿入する回帰検証。生成途中の個別素材全体を原子的に戻す保証はありません |
| 輪郭設定が無関係なdirty assetsを一括保存 | 対象だけ保存し、レベル保存失敗時の旧割当復元を検証 |
| Python更新だけでは過去の取り込み成功マーカーを再使用し得る | ヘルパーのファイル名＋内容ハッシュで自動再取り込み。成功確認後だけ更新ハッシュを記録。時刻・移動先・内容更新・ファイル削除・欠落を実PowerShellで検証 |
| ボタンの解除が実時間で進み、押された保存スナップショットに解除予定がない | ゲーム内時間を使用。読み込み時は標準20/30tickを設定。既存期限をセル再更新で延長せず、破壊で消去するUE統合テストを追加 |
| UE単独モードで矢の衝突からモブへダメージを通知する処理がない | native専用衝突コールバックを追加。同じ衝突を二重適用せず、従来のbridge視覚用矢にダメージを追加しないUEテストを追加 |
| ウィンドウ復帰で古いマウス差分／二度押し履歴が残る | 復帰時の差分を捨て、メニュー・フォーカス切替で二度押し履歴をリセット。ウィンドウ実機検証は未実施 |
| 1.21.11の太陽・月の新画像パスが書き出されない | 選択中リソースパックの新しい太陽と8月相を取得。旧パスも維持。MOD更新と新規書き出しは画像不足時だけ必要 |

## 原作へ近づけた実装

オフハンドの初期所持、交換、インベントリ操作、左右のHUD／モデル、個別の持ち替えアニメーションと保存を追加しました。旧36枠の保存形式は維持し、任意の `offhand` フィールドを追加。不正な値は全体を変更せず拒否します。矢の消費はオフハンドを優先します。プロファイル切替時のスロット初期化も明示し、旧状態が別プロファイルへ持ち越されない回帰テストを追加しました。

段差0.6ブロックは1.21.11の公式クライアントをmapped bytecodeで確認しました。ブロック／エンティティの操作距離をゲームモードに合わせ、サバイバルで岩盤などを即時破壊しない処理を追加。モデル表面のMinecraftスキンはMobもMipMapを無効化しました。

空の時間曲線は1.21.11の `day.json` のcubic_bezierと公式実装を照合し、旧版の余弦曲線を使用しません。方角、太陽／月の見かけの大きさ、月相の安全な剰余、ネザー／エンドでの非表示、雨による透明度を修正。書き出しで光を固定したまま空だけ時間を進める処理は使用しません。

根拠は [Minecraft 1.21.11](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-11)、公式client.jar SHA-1 `ba2df812c2d12e0219c489c4cd9a5e1f0760f5bd` の環境データ・SkyRendering・属性の実装、[Epic ComponentMask](https://dev.epicgames.com/documentation/en-us/unreal-engine/vector-operation-material-expressions-in-unreal-engine)、[マテリアルの透明度](https://dev.epicgames.com/documentation/en-us/unreal-engine/material-blend-modes-in-unreal-engine)です。画像は使用者のリソースパックから取得し、配布物には追加しません。

## クラウドで実行できた検証

- Python取り込み／リソース107件、native書き出し・形式・起動設定38件：計145件成功。PowerShellをPATHへ追加し、スキップなしで実行。
- 実PowerShell 7.4.19：取り込み失敗ログ3シナリオ、ソースハッシュ5シナリオ、ランチャー構文確認成功。
- 本番ヘッダーを実C++コンパイラーで実行：空700項目、キャラクター67項目、輪郭8項目、モブ配置8項目、映像タイミング12項目、映像マスク15ケース成功。
- 照明計算と、メッシュ128ケースの往復／空・充填・床・空洞・境界チェック成功。Python構文と差分検査成功。

MODはJava 21による `test build` が成功し、JUnit 190件は失敗・スキップとも0件でした。配布JARのmetadataは0.13.0で、CRC検証も成功しました。Java＋Pythonは計335件成功です。再実行方法は [CLOUD_SETUP.md](CLOUD_SETUP.md) に記載しています。厳格なAPI代替テストでも、本物のUEモジュールやマテリアルGPUコンパイルを実行したことにはなりません。

## UE実機で未実施の検証

この環境にはUE Editor、Windows、GPUがありません。0.13.0のUEコンパイル・実取り込み・両手描画・IME・衝突・ゲーム保存・FPSは未確認です。利用者のログで成功を確認できたC++ビルドは0.12.1までです。

UE実装を使用するテストとして、`UEBridge.Native.Inventory.OffhandTransfers`、`OffhandSnapshotCompatibility`、`OffhandAmmunitionPriority`、`InitialExportOffhand`、`ProfileReuseClearsPreviousStacks`、`UEBridge.Native.Arrow.ImpactDamagesMobOnce`、`UEBridge.World.ButtonReleaseUsesGameTimeAndRestoresPoweredSnapshots` とキャラクターの段差確認を追加しました。これらはソースに含まれますが実行していません。

爆発は球形の簡易破壊で、爆発耐性・連鎖TNT・爆発のエンティティダメージを原作どおりに計算しません。サバイバルのブロック戦利品も原作のtool／loot tables再現が残ります。盾、オフハンド使用、クラフト、流体、空腹・経験値・防具・耐久値、Mob固有AIなどの未対応事項は [NATIVE_PLAY.md](NATIVE_PLAY.md) を参照してください。
