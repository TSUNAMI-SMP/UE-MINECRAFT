# UEBridge 0.18.6：規則処理のFPS対策とF3・F5競合修正

提供された0.18.5のログでは、通常プレイ中の `rulesMs` が約76〜88msで、通常液体更新・リアリスティック物理は約0.04〜0.08msでした。規則処理が主要なCPU負荷であることが分かりました。規則内のどの段階が支配的かは旧ログだけでは分からないため、負荷経路の修正と段階別の測定を追加しています。MODは **0.18.0** のままのUE専用累積更新です。

## 導入

1. UEを終了し、既存のUEBridgeフォルダーをバックアップします。
2. [UEBridge-update-0.18.6.zip](https://github.com/TSUNAMI-SMP/UE-MINECRAFT/raw/refs/heads/ue-native-play-0.15.0/downloads/UEBridge-update-0.18.6.zip) を展開し、中身をすべて既存の `unreal\UEBridge` に上書きします。ContentとSavedは削除しません。
3. そのUEBridgeフォルダーでPowerShellを開き、以下を実行し、現在の `native_manifest.json` を選びます。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Play-Native.ps1" -Rebuild
```

0.18.4／0.18.5からの更新は **再書き出し・再取り込み不要**です。C++変更を反映するため **`-Rebuild` が必須**です。0.18.0より前からの初回導入は [0.18.0手順](UPGRADE_0.18.0.md) のMOD・書き出しを準備し、初回のみ `-Rebuild -Reimport` を使います。

## 変更

- 遅延イベント：以前は期限の来たイベントを無制限に処理していました。フレーム全体で最大128件／約1.5msに制限し、期限の古いイベントから処理。未処理のイベントを保持します。大量のイベントでは回路・ホッパー・植物の更新完了が遅れる場合があります。
- 草のランダム更新：約1.5ms／最大8192照会、地形変更は最大1件／フレーム。続きのセクションへ順番に進みます。草・土の衝突形状は同じなので、見た目の再構築を既存の地形キューへまとめます。大量の草の成長・枯死は完了まで時間が延びる場合があります。
- 通常落下ブロック：着地・アイテム化は最大8件／約1.5ms、失敗したアイテム生成は20tick後に再試行します。数量は落下物に保持し、失敗で消しません。通常の落下運動は20Hzを維持します。落下物の衝突範囲を常設の範囲へ含め、Receiverが毎フレーム範囲を外して再生成することを防ぎます。
- F3・F5：ネイティブプレイではUE標準のデバッグ入力へ渡す前に処理します。F3はデバッグ表示、F5は視点変更。メニュー中・キー長押し・キーを離した時にもUEのLit／Unlit／カラフルな描画モードへ渡しません。
- 診断：`delayedMs`・`propagationMs`・`grassMs`・`fallingMs`・`delayedRules`・`fallingBlocks` を追加。`paused=true` の時には古い `worldTickMs`／`rulesMs` を現在の時間として表示しません。起動ログのUE版表記を0.18.6に更新。

時間制限はソフトな上限で、開始した1件の更新やメッシュ構築は途中で止めません。規則処理全体・実FPSの保証値ではありません。低FPS時の追いつき処理でも予算をフレーム全体で共有します。

## 確認

同じワールド・場所で通常プレイを確認し、F3で描画色や影が切り替わらず、F5で視点だけが変わることを確認してください。起動ログの `Bridge UE 0.18.6 / MOD 0.18.0` が新版の目印です。性能ログでは、メニューを閉じた **`paused=false`** の行を比較してください。

独立C++・Python・PowerShellの検証は成功しています。この環境にはWindows UE 5.8.3／GPUがないため、UEビルド、キー操作の実機動作、FPS改善量は未検証です。
