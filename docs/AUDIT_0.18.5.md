# 0.18.5 検証記録

2026-10-09。UE専用のFPS優先更新。比較元は0.16.2（8cd11e0）、変更前は0.18.4（972a4d9）。MOD／Java／取り込みPythonは変更していません。

## コード比較で確認した点

0.16.2にない手持ち専用の毎フレームSceneCaptureは0.17.0で追加されていました。ブロック規則も0.17.0の追加です。モブAIと地形照明の基本更新は比較元にも存在するため、この更新で一律に停止していません。画面のFPSだけでCPU／GPUの実際の寄与は確定できません。

## 実行した検証

- `python -m unittest discover -s tools -p 'test_native_*.py'`：58件成功。既存の57件に、本番FIFOの10万件バックログ・重複抑制・256件で中断後の残り保持・処理中の再登録・クリアを検証する1件を追加。PowerShellをPATHに設定した最終実行ではスキップなし。
- `python tools/test_character_math.py`：75項目成功。一人称の左右・攻撃途中・FOV30〜160度・複数アスペクトで、カメラ中心の均等縮小前後の投影が一致すること、元の近接面より前にある標準ブロック頂点が新しい近接面を通過し、プレイヤーの水平衝突範囲内にあることを確認。
- `python tools/test_voxel_index.py -v`：1件成功。全512マスの索引を従来の走査結果と照合。
- `python tools/test_meshing_math.py`：128件の衝突形状変換、面の向きと間引き条件が成功。
- `python tools/test_lighting_math.py`：太陽・遮蔽・編集・松明除去・境界・AO・ライトマップの既存検証が成功。
- Python構文、差分の空白、更新ZIPのCRC・全ソース／ヘルパー一致・SHA-256確認。

## UE実機で未検証の項目

`BridgeWorldTests.cpp` に普通の地形編集が規則キューへ入らないことと、支持されている砂の更新が正常に完了するテストを追加しました。このテストはUE APIを使用するため、Linuxの独立C++検証とは分け、未実行としています。

Windows UE 5.8.3のビルド、近接面変更と手持ちの壁際表示、GPU描画、実FPSは未検証です。ネイティブ終了時には保存した近接面を復元します。独立した投影計算の成功はUEレンダラーの実描画成功を示すものではありません。

伝播キューの時間予算はソフトな上限です。単一の重いメッシュ編集、遅延イベント、大量の通常落下ブロックや光計算は別に時間を使えます。`rulesPeakMs` とUEの `stat unit` を使って更新後の負荷を確認する必要があります。
