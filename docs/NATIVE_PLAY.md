# UE単独プレイ0.13.0の対応範囲と確認

Minecraftからのローカル書き出しをUEへ取り込み、UEで直接描画・操作・保存する実装です。現在の導入操作は [UPGRADE_0.13.0.md](UPGRADE_0.13.0.md) を使います。MOD 0.12.0の既存書き出しにも対応します。Minecraftの全HUD・操作感・ゲームルールを完成させた版ではありません。

## 実装した範囲

| 分野 | 現在の動作 |
| --- | --- |
| 起動 | 1回のnative exportと初回JSON選択。必要なビルド・取り込み・専用マップ保存・起動をPlay-Nativeが開始。C++とPython更新を検出。次回は保存状態を再開 |
| 描画経路 | UEウィンドウへ直接描画。nativeモードでは映像撮影・JPEG圧縮・TCP転送・Minecraftでの復号を実行しない |
| 地形 | 取り込み済みの静的ブロックモデル・衝突・設置・破壊・光伝播。読み込み中は未完成の床への移動を待つ |
| 操作 | キー割り当て、感度・反転、FOV・GUIスケール、しゃがみ／ダッシュ、クリエイティブ飛行、一／三人称、両手・スキン表示。段差0.6、ブロック到達4.5／5、近接3／5ブロック |
| HUD | 手元のリソースパックから取得した照準・ホットバー・ハート・アイコン・フォント。所持数、選択名、インベントリ、クリエイティブ検索、ポーズ・保存・復帰、F3状態表示 |
| インベントリ | 36枠＋オフハンド＋カーソルのスタック、選択・分割・移動・入れ替え、投下・拾得。F交換と弓のオフハンド矢優先。ワールドと同じ保存に含める |
| 空 | 書き出し時点の太陽・月・月相・雨をMinecraft光マップ方式で表示。MOD 0.13.0は1.21.11の新画像を取得。昼夜／天候の継続シミュレーションは未対応 |
| モブ | 対応地上種の外見テンプレートと近くの個体。ゾンビ・村人テンプレートを必須検証。汎用歩行／追跡／攻撃、スポーンエッグ、存在・位置・体力の保存 |
| 音・効果 | 取得した音をUEで再生。ブロックの基本効果、弓、アイテム投下、着火・爆発。Niagara未指定時のnative爆発描画を追加 |
| 永続化 | 地形・プレイヤー・インベントリ・モブ・投下物・着火済みTNTを1ファイルへ保存。読み込みデータを検証してから置き換える |
| 診断 | UEの実フレーム時間／FPS、地形・衝突・光の待ち、照明、モブPalette等を定期ログへ記録。従来の配信経路には受信・表示・交換・古いフレームの計測を追加 |

取り込み時はすべての参照ファイル、サイズ、SHA-256、書き出し完了を検証します。素材が不足・破損している場合は起動準備の成功として扱いません。Minecraftから書き出した同じパッケージを参照し、別の回のスキン・モブ・ブロック素材を自動選択しません。

報告されたモブPalette未作成については、Python取り込みの変数参照を修正し、標準テンプレート・Palette・Receiverへの割り当て・レベル保存を確認します。光の面隣接サンプルが0の場合の処理と、角のAOの暗さを修正しました。ブロック面の法線・頂点順の検証では、法線の反転を必要とする結果は出ていません。粒子の床判定は取り込み地形からも補完します。これらの変更による実際の見た目はWindows実機で確認します。

## 書き出し・保存の境界

- ソースは専用Minecraft 1.21.11の、LAN公開していないシングルプレイです。元ワールドのブロック・インベントリ・モブをUEに合わせて編集する処理はありません。
- 水平半径は4～6チャンク。8ブロックのセルに合わせた有限範囲で、中心セルを含みます。上下は中心セル±6セル、**104ブロックの帯** です。全世界・全高さの書き出しではありません。
- 開始時にMinecraftでロード済みの地形を取得します。書き出し用のチャンク生成要求を追加しません。範囲外のUE地形は生成せず、境界の衝突で移動を制限します。
- 最大2,097,152ブロック行・ワールドファイル512MiB等の上限があります。6チャンクで上限に達する密な地形は、4チャンクなど小さい範囲で書き出してください。
- 時刻・天候・光環境は書き出し時点の情報を使用します。UE内でMinecraft同等に昼夜・天候・空の動きを継続するシミュレーションは未実装です。
- UEの編集は `Saved/NativeWorlds/<識別子>.ndjson` へ保存します。Minecraftへの書き戻しはありません。書き出し元のパッケージは再開時も必要です。
- 保存中は地形・個体・所持数の整合性を保つため、ゲーム時間と編集を一時停止します。保存完了後は再開し、ポーズメニューを開いていた場合はそのまま待機します。60秒ごとの自動保存と終了時保存があります。
- インベントリはアイテムID・数量と表示用モデルを保存します。アイテムの全NBT／Data Components、装備・エンチャント・効果・コンテナの内容をMinecraft同等に保持する仕組みは未実装です。
- モブは対応する外見・基本状態の保存です。MinecraftのエンティティNBT・全行動状態・装備・関係性をそのまま保存するものではありません。

## 完全移植に向けて残る機能

オフハンドからのアイテム使用・盾防御、クラフトとレシピ、食料・満腹度・経験値・防具とサバイバルの全ルール、全コンテナ画面、チャット・コマンド・実績等の全メニューは未実装です。体力・被ダメージ・所持数を扱う部分はありますが、サバイバル全体の再現とは扱いません。

流体、水中・飛行種、モブ固有AI、繁殖・取引・ドロップ、レッドストーン回路、作物やブロックの時間変化、全ブロック固有操作をMinecraft同等に再現する実装は未完成です。静的モデルで表現できない特殊ブロック／アイテムは書き出しの `excluded` へ記録します。

アイテムの光沢・全アニメーション・専用描画、全HUDのレイアウト・全画面、マウス入力や移動物理の完全一致、オートジャンプ・全アクセシビリティ設定の再現は未確認または未実装です。弓は基本ダメージをモブへ与えますが、衝突時速度・クリティカル・エンチャント・矢の保存は未対応です。着火済みTNTの導火線と保存はありますが、導火線中のMinecraft同等のTNTエンティティ表示、爆発耐性・連鎖TNT・エンティティへの爆発ダメージは未完成です。ブロック戦利品のtool／loot tables再現も残ります。

UEの直接描画は従来の映像転送経路による劣化・待ちを取り除きます。ただし、描画負荷・衝突構築・照明更新・GPUドライバー・ウィンドウ表示等の処理は残ります。RTX 5060での実FPSと遅延は実機で測定します。MinecraftとUEでは描画・物理・UIの実装が違うため、「ほぼ完璧な操作感」を確認済みとは扱いません。

## Windows実機での受け入れ確認

クラウドにはUE Editor、Windowsゲーム画面、GPUがありません。MODビルド、Java／Pythonのファイル検証・テスト、UEから独立したC++計算を実行します。**Windows UE 5.8.3の0.12.1モジュールビルド成功は利用者ログで確認済み**です。0.13.0のUEコンパイル、実エディター取り込み完了、実描画、IME、統合動作、実FPSは未確認です。追加したUE自動テストもこの環境では実行できません。

0.13.0の検証ではJava190件・Python145件、空の本番C++計算700項目、移動・入力67項目、光・地形・召喚位置・アウトライン・映像タイミング・マスクの独立した検証が成功しています。実PowerShellによる設定保持と取り込みログ・更新ハッシュの検証も成功しました。詳しい結果は [AUDIT_0.13.0.md](AUDIT_0.13.0.md)、再実行方法は [CLOUD_SETUP.md](CLOUD_SETUP.md) に記載しています。

以下は導入後に順に確認する項目です。成功した範囲を記録し、不成立なら該当ログを保持します。

1. **初回起動**：4チャンク書き出しが完了し、Play-Nativeがビルド・取り込みを完了すること。既存の `/Game/UE` が残り、nativeマップが作られること。Minecraftを終了した状態でゲームが開き、読み込み完了後に床へ立てること。
2. **画像・HUD**：ブロック・自身のスキン・主手・照準・ホットバーが書き出し時の素材を使うこと。F1、F3、GUIスケール、選択名・数量、標準フォントと使用中リソースパックの表示を確認。
3. **入力**：変更した移動キー、感度・上下／左右反転、Mouse4／Mouse5へ割り当てた視点切替、しゃがみジャンプ、前進二度押しダッシュ、ジャンプ二度押し飛行、フォーカスを戻したときのキー解除を確認。
4. **インベントリ**：Eで開閉、英語／日本語検索、IME変換・確定、左／右・Shiftクリック、数字キーによる入れ替え、ホイール選択、Q／Ctrl＋Q投下、拾得の前後で数量が保存されること。Fで両手を交換し、一／三人称・左右設定・オフハンド数量の保存を確認。
5. **地形・光・効果**：設置・破壊、穴の衝突、松明の光と壁越し遮光、屋外・屋根下の面とAO、ブロック破片、弓・TNT・基本音を確認。Escメニューの照明をON→OFF→ONと切り替え、同じ場所で比較。F3の状態・最後の操作結果と、定期診断の値も確認。
6. **モブ**：ゾンビ・村人の卵で1体ずつ生成し、歩行・モデルが表示されること。`missing_palette` が出ず、Paletteのappearance／template数が0でないこと。生成場所が壁や床の内部へずれないこと。
7. **保存・再開**：地形を編集し、所持数を変更し、モブ・投下物を残して保存。ゲームを閉じ、Play-Nativeで位置・視点・所持数・カーソル上のスタック・地形・モブ・投下物を再開できること。別パッケージを選んでも前の保存が保持されること。
8. **失敗処理**：書き出しパッケージのコピーで必須ファイルを欠いた場合、取り込みが失敗し、成功マーカーを作らないこと。元パッケージ・前回保存を保持し、読み込み失敗後に空の所持品や地形を上書き保存しないこと。
9. **性能**：同じ場所・解像度でUEの実FPS・フレーム時間、地形／衝突／光の待ちを確認。1280×720から1920×1080へ、4チャンクから6チャンクへ段階的に比較。nativeモードで映像撮影・転送が動いていないこと。

## 診断用操作

通常の開始に追加操作は不要です。ファイル選択やビルドをやり直す場合は、UEを終了してから `UEBridge.uproject` の隣でPowerShellを開きます。

```powershell
.\Play-Native.ps1 -Reimport
.\Play-Native.ps1 -Rebuild
.\Play-Native.ps1 -Manifest "C:\UEBridgeTest\MC-Test\uebridge-export\native-...\native_manifest.json"
```

`-Reimport` は選んだ書き出しパッケージの素材とnativeマップを再作成します。同じ識別子のUE保存は残り、通常の再開時に使用します。元のMinecraftの状態へ戻すための保存初期化とは別の操作です。

通常ログは `Saved/Logs/UEBridge.log`、取り込み専用ログは `Saved/Logs/NativeImport-日時-識別子.log`、起動準備の記録は `Saved/NativeLauncher.json` と `NativeImportSource.sha256`、保存ワールドは `Saved/NativeWorlds` です。F3はゲーム内の簡易診断です。従来のMinecraft上の `/uebridge video` は配信方式の診断なので、UE単独プレイの実FPSを確認する際はUE側の診断を使用します。
