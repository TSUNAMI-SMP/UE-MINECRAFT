## 更新と起動

初回はMinecraft Java 1.21.11、Fabric Loader 0.19.5、Fabric API 0.141.6+1.21.11、Java 21と、UE 5.8・Visual StudioのC++ビルド環境を用意します。一式ZIPのMODは `UE-MINECRAFT/artifacts`、UEプロジェクトは `UE-MINECRAFT/unreal/UEBridge` にあります。Minecraftの素材は利用者の環境で書き出します。

1. MinecraftとUEを終了します。Minecraftのmodsフォルダーで旧UEBridge MODを外し、0.16.0 JARを入れます。
2. Minecraft 1.21.11で対象のワールドを開き、`/uebridge native export` を実行します。完了した**新しい** `native_manifest.json` の絶対パスを控えます。水・溶岩のモデル、粒子画像、専用ブロック用の形状を今回追加したため、旧書き出しは使い回せません。
3. UE更新ZIPを展開し、全内容を**使用中の `UEBridge.uproject` があるフォルダー**へ上書きします。Sourceと全Pythonヘルパーが必要です。フォルダーを丸ごと削除する必要はありません。
4. 同じフォルダーでPowerShellを開き、新しい書き出しのパスを入れて実行します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Play-Native.ps1" -Manifest "C:\UEBridgeTest\MC-Test\uebridge-export\新しい出力フォルダー\native_manifest.json" -Rebuild -Reimport
```

この実行ではC++を再ビルドし、素材・生成マテリアル・専用レベルを取り込み直して起動します。`-Rebuild -Reimport` の両方を付けてください。完了後は `Play-Native.cmd` のダブルクリックで再開できます。Minecraftはプレイ中に起動しておく必要はありません。

新しい書き出しは別パッケージです。以前の `Saved/NativeWorlds` と書き出し元フォルダーは残してください。旧パッケージのUE編集・所持品を、新しい書き出しへ自動移行する仕組みはありません。

ビルド・取り込みが失敗した場合は、`UEBridge\Saved\Logs\NativeImport-*.log` と `UEBridge\Saved\Logs\UEBridge.log` を確認します。

## 操作

| 操作 | キー |
| --- | --- |
| 一人称 → 後方三人称 → 前方三人称 | F5 |
| 照明の切り替え | F6 |
| チャット | T（書き出した設定で変更可能） |
| コマンド入力 | /（書き出した設定で変更可能） |
| 投下／スタック投下 | Q／Ctrl＋Q（書き出した設定を使用） |
| インベントリ／保存メニュー | E／Esc（インベントリは書き出した設定を使用） |

F5を視点切り替えに固定しました。Minecraftでサイドボタンに割り当てていても、UEではF5を使います。チャット入力中は視点・移動・インベントリのショートカットを止めます。Enterで実行、Escで閉じます。

実装したチャットはUE内だけで動きます。Minecraftサーバーや他のプレイヤーへの送信はありません。

```text
/time set day
/time set noon
/time set night
/time set midnight
/time set 6000
/time add 1000
/time query daytime
/time query day
/time query gametime
/gamerule doDaylightCycle false
/gamerule doDaylightCycle true
/weather clear
/weather rain
/weather thunder
/gamemode creative
/gamemode survival
/give water_bucket 1
/give lava_bucket 1
/give diamond_sword 1
/save
/help
```

時間は20 tick/秒、1日24000 tickで進み、時刻・時間サイクル設定・天候を保存します。`/weather` は空と照明の変更です。雨粒と落雷は未実装です。チャットの入力欄にはOSのフォントを使い、履歴は取得したMinecraftの文字画像で表示します。

## 今回の変更

| 対象 | 変更 |
| --- | --- |
| 中央の＋ | HUDの座標をビューポート全体の比率へ変換。画面サイズと内部描画解像度の差による位置ずれを修正。表示は12 GUIピクセルへ縮小 |
| 文字 | 文字の位置・幅・高さを整数ピクセルへ合わせ、既存の暗い影を保持 |
| しゃがみ | 移動量の端判定に加え、UEが後から落下へ切り替える処理にも足元の支えを確認。支えがある場合は足の高さを保持 |
| 通常・ダッシュ攻撃 | 原作の抵抗、水平速度の半減、地上時の上向き上限、ダッシュの追加押し出しを使用。空中の重力・抵抗・変位を20 tickの計算へ変更 |
| クリティカル・範囲攻撃 | 攻撃チャージ、落下、接地、ダッシュの条件で判定。クリティカル1.5倍、剣の範囲攻撃、対応音・粒子・腕の振りを接続 |
| モブの死亡 | 行動入力を消して重力を保持。倒れた表示モデルの最下部を床へ合わせ、20 tick後に死亡粒子と削除 |
| モブの向き | 胴体を目標方向へ回してから前方へ歩かせる。向きが違うまま横へ滑る入力を抑制 |
| 設置のフェード | ネイティブ表示では時間方向のアンチエイリアスを無効化。設置・描画更新は透明度の遷移を使わず反映 |
| 水・溶岩 | 流体行を除外せず、液面の高さ・隣接面・角の高さ・透明度・テクスチャのアニメーションを描画 |
| 液体の操作 | バケツで設置・源の回収、水を含むブロック、泳ぐ移動と浮上、目線の色、酸素表示、溺れ・溶岩ダメージ |
| 流れ | 上下・水平のレベル更新、水源の生成、基本的な水／溶岩の反応、ネザーの水設置制限。編集した液体も保存・再開 |
| ブロック対象 | 専用描画ブロックの一律除外を解除。通常モデルがない場合は取得したアイテムのNONE形状を地形の光で表示。不可視ブロックは表示せず衝突を保持。ベッドの2ブロック設置・破壊も追加 |
| 粒子 | 取得したクリティカル・剣の範囲攻撃・落葉画像を使用。桜・ペールオークを分け、通常の葉は周辺の色を使用 |
| 投下 | Qで1個、Ctrl＋Qでスタック。原作の前方初速・上向き初速と40 tickの回収待ちを適用。所持数・投下物・回収待ちを保存 |

## 実機で確認する項目

1. ウィンドウを変更し、FOV・GUIスケール・内部描画解像度を変えても＋が画面中央に残るか。通常画面とインベントリの文字影も比較します。
2. 平地でしゃがんで前・後・斜めに端へ進み、落下しないか、足の高さが下がらないか。階段・ハーフブロックも別に確認します。
3. 地上の通常攻撃、ダッシュ攻撃、落下中のクリティカル、空中での追撃を比較します。無敵時間とチャージ、死亡時の床・空中の両方を確認します。
4. モブの歩く方向と胴体が一致するか、曲がり角や押し戻された直後に不自然に跳ねないかを確認します。
5. バケツで水・溶岩を置く／回収する、水を含むブロックを置く／壊す、泳ぐ、息とダメージ、液体を編集して保存・再開する操作を確認します。
6. 草、ガラス、葉、ドア、階段、ベッド、チェストなどを設置します。フェード・欠けた面・手持ちのチカチカ・特殊形状を別々に確認します。
7. F5/F6、T、/time、時間停止と保存・再開、Q/Ctrl＋Q投下と2秒後の回収、剣・クリティカル・落葉の表示を確認します。

## 残る範囲

**全モブ固有AI・全ブロック機能・バニラ完全一致は完成していません。** 今回のAI変更は既存の歩行・経路・注視・追跡の調整です。全種のGoalSelector/Brain、繁殖・取引・群れ・種別固有攻撃の完全移植は残っています。

流体更新は有限範囲で動く基本実装です。原作の流出先の最短探索、水泳姿勢とダッシュ泳ぎ、気泡柱の推進、溶岩を出た後の燃焼、火・玄武岩生成などは未対応です。テクスチャの非標準フレーム順・補間も原作と同一ではありません。

ブロックIDの書き出し対象と設置対象を広げましたが、全状態の見た目と固有機能を実機で確認した結果ではありません。通常モデルがなくNONE形状も取得できないものは仮の石の形状です。専用形状の向き・接続・アニメーション、看板の文字、コンテナ、レッドストーン、特殊ブロックの動作には追加実装が必要です。

今回はJava/Python/独立したC++計算を検証しています。**Windows UE 5.8.3のコンパイル・ShaderCompileWorker・GPU描画・入力・実FPSは未検証です。** このZIPはローカルでビルドするソース更新です。
