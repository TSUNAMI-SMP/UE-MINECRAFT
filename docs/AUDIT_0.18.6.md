# 0.18.6 検証記録

2026-10-09。変更前ca69d0c（0.18.5）。ユーザーの通常プレイログで `rulesMs` 約76〜88ms、物理ソルバー約0.06ms、液体更新約0.04〜0.08msを確認しました。`pendingRules=0` でも規則時間が約80msなので、伝播キューだけの0.18.5対策では負荷を解消できていません。旧ログには規則内の段階別計測がなく、遅延・草・落下の個別寄与は未確定です。

## 未実行・制限

Windows UEのコンパイル、UE Automationテスト、実キー入力と描画、実FPS測定は未実行です。独立C++検証は予算クラスの動作を検証し、UE内の地形再構築・衝突・イベント動作を代用しません。

時間予算はソフトな上限です。1件の処理・遅延マップの走査／整列・地形キューの再構築・落下運動などの時間は、個別に予算を超え得ます。遅延イベントは消去せず保持し、走査が予算を超える場合も先頭の1件は進めます。草更新・大量回路・大量の着地処理は完了まで時間が延びます。保存形式は変更せず、既存の数量を維持します。
