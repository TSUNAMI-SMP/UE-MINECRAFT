# 0.19.0 検証記録

2026-10-09。変更前c4fc6fe（0.18.6）。利用者から、FPS低下問題が解消し安定して最大100fpsを維持しているとの報告がありました。今回の水源付きの性能は別途確認が必要です。

## 実装と検証

- 再照明キューが地形再構築の4ms期限を共有していたため、再構築が続くと再照明が後回しになり得る経路を修正。再照明専用の2ms予算を追加し、初期光の完了時にもセルを再照明します。黒い面の再現・解消をUEで確認したものではありません。
- 通常表示をLighting ON／影OFF／全体リアル表示OFFに固定。専用GPU水のアセット素材には稼働中だけ反射を有効にします。水源なしのSceneCapture増設はありません。
- Niagara水のコピー先に既存アセットがある場合は保持し、非Niagaraアセットは拒否します。正確なFLIP Hose以外のPool／Gasを代用品にしません。
- 水源の上限2・領域重複・非有限座標を保存の読み込み前に検査。不正なデータは既存状態を変更せず拒否します。旧セーブには水源フィールドがなくても対応します。GPU粒子のスナップショット保存はありません。
- `python -m unittest discover -s tools -p 'test_native_*.py'`：59件成功、スキップなし。既存PowerShell fixtureと、本番水源ポリシーヘッダーのC++17検証を含みます。
- `test_realistic_niagara.py`：8件成功。水用テンプレート探索、既存アセット保持、誤った型、代用拒否を検証するPython fixtureです。実エンジンのアセットロードの代用ではありません。
- `test_realistic_materials.py`：1件成功。既存素材生成fixtureと、水テンプレート未発見時に取り込みを続ける経路を検証。
- `test_realistic_physics.py`：2件成功。従来の有限量液体等の独立C++検証。
- `test_lighting_math.py`、`test_sky_math.py`（714項目）、`test_character_math.py`（75項目）、`test_meshing_math.py`（128衝突形状変換等）は成功。
- Python構文、差分空白、更新ZIPのCRC・ソース／ランチャー／ヘルパー一致、SHA-256を検証。

## 未実行・未完成

Windows UE 5.8.3のC++ビルド、追加したUE Automation保存テスト、Niagara Fluidsの実取り込み・GPU実行・地形衝突・保存再開・実FPS測定は未実行です。公開UEヘッダーでパラメーター列挙、Position変数と固定BoundsのAPIを確認しましたが、UE 5.8.3の実ビルド成功を意味しません。

水源の領域と数はアプリ側で制限します。粒子上限・寿命・継続放出と境界条件はアセット側の設定にも依存します。未接続のUserパラメーターは実行時の名前検査だけでは検出できません。使用するテンプレートの実モジュール接続を確認する必要があります。

白波・泡・水しぶきの調整、実際の透明度／屈折／反射、写実品質は未完成です。現在のSSRは画面外の反射を復元できません。インスタンス地形の衝突対応、泳ぎ・モブの水中判定、溶岩反応、GPU水の動画記録にも未対応／未検証の範囲があります。詳細は [NIAGARA_WATER.md](NIAGARA_WATER.md) に記載します。
