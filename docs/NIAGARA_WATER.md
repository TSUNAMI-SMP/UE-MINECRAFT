# 無料Niagara Fluidsの水：0.19.0の連携と実機確認

採用する素材は、Unreal Engineに付属する **Niagara Fluidsの `Grid3D_FLIP_Hose`** です。追加購入は不要です。使用・配布にはUnreal Engineの利用条件が適用されます。この更新ZIPはエンジンのアセット自体を配布せず、インストール済みエンジンからローカルの水用システムを作ります。

今回完成したのは、水用アセットを呼び出す経路、水源の操作・保存、計算範囲の制限です。**UE 5.8.3でのテンプレート互換性、実際の描画・衝突・性能は未確認です。「現実と見分けがつかない水」の完成版ではありません。** 強い流れ、水面の透明度・屈折、少量の白波・水しぶきは、実機のアセット調整と評価が必要です。Minecraftの色や反射へなじませる補正は追加していません。

## アセットの準備

`Play-Native.ps1 -Rebuild -Reimport` のビルド処理は、インストール済みのNiagara Fluidsプラグインを有効にします。取り込み処理は `/NiagaraFluids` 以下の `Grid3D_FLIP_Hose` を検索し、`/Game/Bridge/Realistic/NS_RealisticWater` へ複製します。同名の既存Niagara Systemは保存して、利用者の編集を上書きしません。PoolやGasを水源の代用品にはしません。

テンプレートがレジストリから見つからない場合は、水の設置を止め、バケツを保持します。UEエディターで次の準備を行います。

1. Niagara Fluidsプラグインを有効にしてエディターを再起動します。
2. Niagara Systemの新規作成画面で、Niagara Fluidsの液体テンプレート `Grid3D_FLIP_Hose` を探します。必要に応じてプラグイン／エンジンコンテンツを表示します。名前・提供形式はUEの版によって異なり得ます。
3. ホースから継続的に液体を放出するテンプレートを使い、`Content/Bridge/Realistic/NS_RealisticWater` として保存します。該当するテンプレートがない場合は、別の効果を同名にして代用しないでください。
4. 以下のUserパラメーターと、シミュレーション／発生モジュールへの接続を確認します。**未接続のUserパラメーターを名前だけ追加しても制御できません。**

| 制御 | 対応する名前と型 | 設定値 |
| --- | --- | --- |
| 必須：領域のサイズ | `User.World Grid Extents`、`User.WorldGridExtents` または `User.WorldSpaceSize`：Vector3 | 1000×1000×800 cm |
| 必須：最大軸のセル数 | `User.Num Cells Max Axis`、`User.NumCellsMaxAxis` または `User.ResolutionMaxAxis`：Integer | 128 |
| 任意：放出位置 | `User.SourcePosition` または `User.SourceLocation`：PositionまたはVector3 | 水源のワールド座標 |
| 任意：初速度 | `User.SourceVelocity`：Vector3 | (0, 0, -450) cm/s |
| 任意：発生率 | `User.SpawnRate` または `User.SourceSpawnRate`：Float | 12000 |

位置・速度・発生率のパラメーターが存在しない場合はテンプレートの既定値を使います。その場合、継続放出が有効で、発生位置がシステムの原点にあり、原点から下向きに流れることをエディターで確認してください。水用Actorの位置と固定Boundsの中心は設置位置です。位置パラメーターをローカル座標として扱うアセットには、上記のワールド座標をそのまま接続できません。

Niagaraの地形衝突用データインターフェースが `collider` タグを参照するよう確認します。地形Actorにはこのタグを付けていますが、既存のインスタンス衝突形状を液体テンプレートが利用できるかは未検証です。平面、階段、壁、ブロック編集後の衝突を実機で確認する必要があります。水面のマテリアル・スプラッシュ・泡はテンプレート側の構成を使用し、独自のVFXメッシュは追加していません。

## 水源の仕様

- 同時に最大 **2水源**。各水源は設置場所を中心に **10×10×8ブロック**、最大軸128セルの領域を持ちます。領域同士の重なりと、書き出し範囲からはみ出す設置を拒否します。
- 源はバケツ1杯で終わる有限量ではなく、アセットの放出処理を動かし続ける仕様です。領域外へ広がり続ける水、領域間での水の受け渡しは対象外です。領域端の排出／消滅と粒子寿命はテンプレートの設定を実機で確認します。
- プレイヤーが水源から32ブロックを超えると停止・表示を解除し、戻ると最初から放出を再開します。水源がなければGPU液体のインスタンスを作りません。反射を有効にするのも水の稼働中です。
- 保存するのは水源位置です。GPU内の粒子状態は保存せず、再起動時は水源から流れ直します。
- 空バケツは、壁に遮られていない水源位置を狙った場合に回収できます。流れている水粒子から新しい水バケツを複製する操作はありません。
- `/physics clear water all` で全水源と旧方式の水を削除できます。`/physics undo` は直前の削除前の状態を戻します。取り消し履歴は再起動すると消えます。
- `/realistic quality` は従来の砂・溶岩等の品質に作用します。新しい水の解像度は今回128に固定しています。

旧セーブの有限量の水は旧ソルバーで保持します。新しい水源へ自動変換しません。GPUの水は現時点では泳ぎ・モブの水中判定・溶岩との反応に接続していません。オフライン動画記録も未対応なので、水源がある状態で `/record start` は拒否し、記録中には水源を設置できません。

## 実機での確認順

1. 水源なしで同じ場所をプレイし、改善済みのFPSに回帰がないことを確認します。再起動後の黒い面とF3・F5も確認します。
2. `/realistic items` でアイテムを追加し、平らな場所へ水源を1個置きます。`Bridge Niagara water:` のログで使用アセットと設定されたパラメーターを確認します。エラー時はバケツが減らないことを確認します。
3. 継続放出、領域端、平面・段差・壁への衝突、ブロックの破壊と設置を確認します。水面が黒くなる／床を抜ける場合は完成扱いにせず、アセットのマテリアル・衝突設定を調整します。
4. 保存・終了・再開、32ブロック以上離れて戻る、空バケツで回収、削除・取り消しを確認します。水源2個と3個目の拒否、重なる領域の拒否も確認します。
5. RTX 5060で `stat unit` と `stat gpu` を比較し、放出率・粒子上限・寿命とVFX負荷を調整します。2水源時の100fpsは未保証です。

白波・泡の量、流速、透明度、屈折、画面外の反射の不足はこの評価後に詰める項目です。SSRは画面外の情報を反射できないため、現在の反射経路だけであらゆる角度の写実性を満たすとは限りません。

## コンパイルエラー（メッシュディスタンスフィールド）

`Get Closest Point Mesh Distance Field No Normal` が生成無効のエラーになる場合は、プロジェクト設定で Generate Mesh Distance Fields を有効化し、エディター再起動と生成処理の完了後に水アセットを再コンパイルして保存します。利用者のUE 5.8.3で、この設定により10件のエラーが解消し、警告付きのコンパイル成功を確認しました。水の実設置・地形衝突・100fps維持は別途確認が必要です。0.19.3はアセットのパラメータ名への対応で、エンジンアセットやプロジェクト設定を上書きしません。
