# UEBridge 0.15.4 更新手順

0.15.3で取得した診断結果を基に、入力・描画・ノックバック・モブの基本動作を変更した版です。

- [MOD 0.15.4](https://github.com/TSUNAMI-SMP/UE-MINECRAFT/raw/refs/heads/ue-native-play-0.15.0/downloads/minecraft-ue-bridge-0.15.4.jar)
- [UE更新ZIP 0.15.4](https://github.com/TSUNAMI-SMP/UE-MINECRAFT/raw/refs/heads/ue-native-play-0.15.0/downloads/UEBridge-update-0.15.4.zip)

## 適用

1. MinecraftとUEを終了し、旧MODを0.15.4 JARへ交換します。同じUEBridge MODの複数版を併用しないでください。
2. Minecraftで `/uebridge native export` を実行します。今回、原作の面ごとの両面描画設定を追加したので、新しい書き出しが必要です。
3. UE更新ZIPの全内容を、既存の `UEBridge.uproject` があるUEBridgeフォルダーへ上書きします。SourceとPythonヘルパーの両方を更新してください。
4. 新しい `native_manifest.json` のパスで以下を実行します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Play-Native.ps1" -Manifest "C:\UEBridgeTest\MC-Test\uebridge-export\新しい出力フォルダー\native_manifest.json" -Rebuild -Reimport
```

このPowerShellプロセスにだけ実行ポリシーを設定します。C++再ビルドと生成マテリアルの再取り込みが必要です。

新しい書き出しは別パッケージの初期状態です。旧パッケージ・UEのSavedを残してください。以前のUEプレイ中の編集や所持品を、新しい書き出しへ自動移行する変更ではありません。

## 変更と確認項目

- 真下を向いた時の折り返し：UEの角度の正規化結果を次のマウス入力へ読み戻さず、符号付きのピッチを保持。真下へ動かし続けても上へ飛ばず、その後上向きへ戻せることを確認してください。
- 面の描画：変換後の頂点と外向き法線から三角形の表裏を選択。アイテムは原作RenderPipelineのカリング設定を取得し、両面が必要な面だけ逆向きの三角形も作ります。反射した左手モデル・薄いアイテム・ドロップ品も対象です。
- 草のチカチカ：手持ち・ドロップモデルでも、重なる同じ向きの面へ描画専用の深度差を付けます。照明・衝突の座標は変更しません。
- アウトライン：四面の筒を重ねる形から、カメラへ向いた一枚の帯に変更。新しい `M_BlockOutline_v2` を作り、40%アルファ、画面上で約2ピクセルを使います。
- ノックバック：同期的に速度を合成し、上向きの押し出し前に落下モードへ切り替えます。着地した直後の接地判定を補い、死亡時も重力を維持します。地上の通常攻撃・ダッシュ攻撃・空中の追撃・死亡で確認してください。
- モブ基本AI：押し戻された速度で胴体が逆を向く挙動を除去。有限時間のプレイヤー注視・周囲を見る行動を移動判断から分離。見えていないプレイヤーを新規に追い始めず、取得済みの対象は遮蔽後最大60ティックだけ保持し、斜めの経路と角の衝突確認を追加。

## 診断から確認できたことと残る範囲

診断は全481クラス、200サーバーティックが取得成功しました。ハスクへの攻撃を7回記録し、最初の被ダメージ時に上向き速度0.313600006ブロック/ティックを確認しました。実行中のLookAtEntityGoalでは頭と胴体の角度が異なり、後にWanderAroundGoalが実行されています。

診断時の手持ちはairでした。周辺の草・土・葉などのモデルは取得できていますが、問題が出ている手持ちアイテムの実モデルや、UEで描画された全地形の状態はこのZIPにはありません。面の欠落全体の原因が確定した、あるいは全問題が実機で解消したという結論ではありません。

今回はUEの移動・描画に対する修正を加えましたが、全モブのGoalSelector/Brain、繁殖、種別固有の攻撃・社会行動の完全移植ではありません。ノックバックの計算は原作を参照していますが、衝突・重力の実行はUE CharacterMovementを使用します。

文字影と照明は0.15.2の実装を維持しています。この診断にUEの文字影・GPU描画結果が含まれていないため、原作との一致を確認できたとは扱いません。

Windows UE 5.8.3実ビルド、GPU描画、入力、実戦闘はこの環境では未実行です。Java/Python/独立C++検証の範囲は [検証記録](AUDIT_0.15.4.md) を参照してください。
