# Windows shared GPU video

The 0.11.0 MOD embeds a Windows x64 JNI DLL. No local Minecraft images, skins or sounds are part of this native library.

UE's optional **D3D11** path converts its float-linear capture to straight-alpha sRGB BGRA8 on the GPU. Three shared textures have explicit frame leases. The TCP packet contains only the matching camera/input sequence and texture handle, adapter LUID, slot and generation. The producer polls a GPU completion query before announcing a frame. Minecraft opens the shared D3D11 resource on that adapter, registers it with `WGL_NV_DX_interop2`, locks it, copies into its own `GlTexture` using `glCopyImageSubData`, unlocks, then acknowledges the lease. Frames overwritten before presentation are also released. No CPU pixel readback, JPEG, CPU decode, or per-frame texture upload occurs on this path.

When the RHI is D3D12, the DLL/extension is unavailable, an adapter cannot share, or GL registration/copy fails, JPEG continues. This implementation does **not** claim D3D12 interoperability. D3D11 changes which UE rendering features are available; retain the usual D3D12 launch when evaluating Lumen lighting.

`Launch-UEBridge-GPU.cmd` beside the existing `.uproject` opens saved `/Game/UE` as `-game -d3d11 -windowed -ResX=1920 -ResY=1080`. Save/close the editor first. Other saved levels can be selected with `Launch-UEBridge-GPU.ps1 -Level /Game/your_level`. These options do not modify project configuration. Use Minecraft `/uebridge video transport auto`, `/uebridge video quality ultra`, `/uebridge video fps 30`; compare with `transport jpeg` using the same scene and D3D11 launch. Forced `transport gpu` still reports/falls back when sharing is unsupported.

The receiver counts distinct received and draw-submitted UE frames separately. Latency percentiles measure echoed input packet send time to Minecraft's draw submission. They do not measure mouse hardware, buffer swap, monitor scan-out or photon latency. Windows/UE/GL interoperability and the RTX 5060 performance target require PC validation; cross-compilation and loopback protocol tests are not that validation.

Build from source with `Build-NativeVideo.cmd` in an x64 Visual Studio Native Tools prompt, with `JAVA_HOME` pointing to a Java 21 JDK; copy the resulting DLL to `minecraft-mod/src/client/resources/native/win64/uebridge_gpu.dll` before building the MOD. The released DLL is cross-built using MinGW-w64 GCC with `tools/build_native_video.py --toolchain-root ... --jdk ...`. It links GCC runtimes statically (GCC Runtime Library Exception) and imports only Windows system libraries: d3d11, dxgi, opengl32, kernel32 and msvcrt. It requires no separate MinGW/Visual C++ runtime installer. The build helper also compiles the native producer in isolation; this is not an Unreal module build.
