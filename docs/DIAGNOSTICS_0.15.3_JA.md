# コード・実測データ取得用MOD 0.15.3

今回は診断MODのみです。UE側の修正は診断結果の確認後に行います。UE更新、再ビルド、native export、再取り込みは不要です。

[診断MODをダウンロード](https://github.com/TSUNAMI-SMP/UE-MINECRAFT/raw/refs/heads/ue-native-play-0.15.0/downloads/minecraft-ue-bridge-0.15.3.jar)

1. Minecraftを終了し、`mods` 内の旧 `minecraft-ue-bridge-*.jar` をこのJARに置き換えます。同じMODの旧版と併用しないでください。Minecraft Java 1.21.11、Java 21、Fabric Loader 0.19.5以上、対応Fabric APIを使用します。
2. シングルプレイで、問題の場所に近い草ブロック・木・葉がある場所へ移動します。草ブロック、または面が消えるアイテムを手に持ち、近くに豚・牛・羊などのモブを用意してください。
3. 以下を順に実行します。

```text
/uebridge control off
/uebridge off
/uebridge diagnose export
```

4. メニュー・チャットを閉じて約10秒プレイします。普通の攻撃とダッシュ攻撃を行い、モブが上下に跳ねる様子を記録します。カメラは上から真下へ動かしてください。記録中にポーズメニューを開くとサーバーティックが止まります。
5. 「診断ZIPを保存しました」のパスを開き、`diagnostics-*.zip` をチャットに添付してください。通常は使用中のMinecraftゲームフォルダーの `uebridge-export` に保存されます。`native_manifest.json` ではありません。

1回の記録は最大32体、開始位置から水平32ブロック・上下16ブロックのモブを200サーバーティック記録します。周辺ブロックは水平8ブロック・上下4ブロック、モデルは草・手持ち・照準先を優先した最大8種類です。異なるアイテムも調べる場合は、それを持ってコマンドを再実行してください。記録中にワールドを終了した場合は取得済みの部分だけ保存し、その旨をZIP内に記録します。

## ZIPの内容

- `classes/`: AI・Brain・経路探索・戦闘・マウス・カメラ・ブロック／アイテム／文字描画など、481クラスの取得を試みます。
- `classes.tsv`, `mappings.tiny`: Yarn 1.21.11+build.6の名前対応表。Minecraft本体のコードは診断MODに同梱せず、実行時に利用者のインストールから取得します。
- `class-report.json`: 実行時の名前、各ファイルのSHA-256、取得できなかったクラス。
- `snapshot.json`: 選択した操作・表示設定、周辺のロード済みブロック、形状・描画色、モブ／プレイヤーの位置・速度・接地・向き・ダメージ状態、AI Goalの優先度・実行状態。
- `resources/`: 有効なリソースパックから選択したモデル・テクスチャ。参照先をたどりますが、件数・容量には上限があります。

`.class` は解析可能なクラスデータであり、`.java` ソースそのものではありません。クラスローダーのリソースとして取得するため、Mixin適用後のメモリー上のコードと完全に同じとは限りません。Brain型AIの実行中タスクの列挙は含めず、関連クラスと移動の実測を取得します。

ワールド、モブ、所持品を診断処理から変更しません。アカウント情報・認証トークン・チャット・ログ全文・Minecraft本体JAR全体は収集しません。ZIPにはゲーム内座標・モブID・リソースパック名が含まれます。自動送信はありません。

## 検証範囲

Java 21でのコンパイル、JUnit、配布JARの構成を検証します。対象481クラスは開発用named JAR／配布用intermediary JARの両方で存在を確認しました。ZIPのパス検証・重複拒否・サイズ制限・クラスヘッダー・SHA-256も検証します。GUIでのMinecraft実起動、実際のモブ攻撃による取得結果はこの環境では未確認です。

Yarnの名前対応データはFabricMC Yarn 1.21.11+build.6由来です。再生成は `minecraft-mod/tools/generate_diagnostic_index.py` に当該バージョンの `mappings.tiny` のパスを渡して行えます。
