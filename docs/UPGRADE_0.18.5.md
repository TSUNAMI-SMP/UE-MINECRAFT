# UEBridge 0.18.5：通常プレイのFPS回帰対策

0.16.2以降の追加処理を比較して、物理未使用でも動く負荷を修正したUE専用の累積更新です。MODは **0.18.0** のままです。0.18.0〜0.18.4で使っている書き出しを再利用でき、Minecraftからの再書き出しは不要です。

## 導入

1. UEを終了し、既存のUEBridgeフォルダーをバックアップします。
2. [UEBridge-update-0.18.5.zip](https://github.com/TSUNAMI-SMP/UE-MINECRAFT/raw/refs/heads/ue-native-play-0.15.0/downloads/UEBridge-update-0.18.5.zip) の中身を**すべて**既存の `unreal\UEBridge` フォルダーへ上書きします。保存ワールド・Content・Savedは削除しません。
3. そのUEBridgeフォルダーでPowerShellを開き、実行します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Play-Native.ps1" -Rebuild
```

ファイル選択画面で、現在使用中の `native_manifest.json` を選んでください。今回の差分はC++なので、0.18.4からの更新に素材の再取り込みは不要です。**`-Rebuild` は必須**です。

0.18.0より前から初めて導入する場合は、[0.18.0導入手順](UPGRADE_0.18.0.md) のMODと書き出しを準備して本ZIPを適用し、初回だけ `-Rebuild -Reimport` を指定します。

## 修正した負荷

- **一人称の追加描画**：0.17.0で追加された、全画面サイズの手持ち専用SceneCaptureを毎フレーム動かす経路を除去。腕・手持ち・オフハンドを通常画面で描きます。カメラ中心で位置とサイズを均等に縮小することで画面上の大きさを保ち、標準モデルをプレイヤーの衝突範囲内に置きます。元の手持ちFOV補正・アニメーションは維持します。通常のブロック／腕での投影計算は検証済みですが、特殊な大型モデルや実際の壁際表示はUE実機で確認が必要です。
- **不要なブロック規則**：普通の石・土まで更新待ちに入れる処理を除き、支持されている砂・花で周辺レッドストーンを評価しないようにしました。オブザーバーへの変更通知は維持しています。
- **更新待ちキュー**：削除済みの穴がある集合を毎回先頭から探索する方式から、重複を抑えたFIFOへ変更。処理済みブロックの再登録も可能です。
- **低FPS時の追いつき処理**：伝播更新の上限をフレーム全体で共有し、最大256件／約2msにします。未処理分は捨てず次へ残します。1件のブロック更新中には中断できないため2msは厳密な上限ではありません。大きな回路や大量の初期更新は完了までの時間が延びる場合があります。草のランダムtick、遅延イベント、通常の落下ブロックの20Hz処理は維持しています。
- **ブロック情報取得**：利用できる場合は既存のマス索引を使い、全行の照会を省きます。

照明・物理・モブ等を丸ごと無効化してFPSを上げる変更ではありません。既存の設定と保存ワールドを維持します。表示設定の整理、再起動後の黒い面、既存アセットによる物理・Niagaraの差し替えは、このFPS優先更新では完了していません。

## 更新後の確認

同じワールド・同じ場所・同じ視線で、照明ON／影OFF／リアル表示OFF、録画停止の状態を比較してください。空を向いた停止画面と地形を見た通常プレイの比較だけでは、GPUとCPUの負荷を切り分けられません。

新しいコードが動いている場合、`Saved\Logs\UEBridge.log` の `Bridge native performance:` に **`hands=main_view`** が出ます。`rulesMs` は直近のブロック規則のCPU時間、`rulesPeakMs` は前回の診断からの最大値、`pendingRules` は処理待ち件数、`fluidsMs` は直近の通常液体更新時間です。`worldTickMs` は地形Actorの平滑化したCPU時間で、GPU・描画スレッドや他のActorは含みません。自動ログに加え、チャットの `/diagnostics` でも取得できます。

まだ低FPSならUEコンソールで `stat unit` を表示し、Game／Draw／GPUとログを照合してください。更新後のログと同じ場所のスクリーンショットがあれば、残る負荷を追えます。

この環境にはWindows UE 5.8.3／GPUがないため、UEコンパイルと実FPSは未検証です。0.16.2との差分から負荷候補を除去していますが、10fpsの原因の断定や60fpsへの復帰を保証する測定結果ではありません。
