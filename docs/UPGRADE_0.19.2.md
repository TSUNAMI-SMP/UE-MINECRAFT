# UEBridge 0.19.2：保存済み落下ブロックの復元修正

提供されたセーブには砂利・砂の落下時間 `age` が604〜619の状態がありました。保存側はこれを出力できましたが、読み込み側が600以下しか受け付けず、`Saved falling blocks invalid; save preserved` で操作が止まっていました。約Y=-49に残った期限切れの落下物もあり、書き出し範囲外のデータを保持する復元経路を追加しています。

## 適用

UEを終了して既存フォルダーをバックアップし、[UEBridge-update-0.19.2.zip](https://github.com/TSUNAMI-SMP/UE-MINECRAFT/raw/refs/heads/ue-native-play-0.15.0/downloads/UEBridge-update-0.19.2.zip) の中身を既存の `unreal\UEBridge` へ上書きします。**Savedの削除・falling配列の手動削除は不要です。** 0.19.1のビルド修正を含む累積更新です。

0.19.1で取り込みまで完了している場合は以下を実行します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Play-Native.ps1" -Rebuild
```

0.19.0の水アセット取り込みがまだ完了していない場合は `-Rebuild -Reimport` を使います。MODは0.18.0のまま、現在の `native_manifest.json` と保存済みワールドを使います。起動ログは `Bridge UE 0.19.2 / MOD 0.18.0` です。

## 修正内容

- 過去の整数の落下時間を読み込み、600を超えた状態は期限切れの601として扱います。再開後の経過時間も601で止め、値が増え続けないようにします。落下物1個を削除して通過する処理は追加していません。
- 期限切れ・停止中でワールド下端より下にある旧落下物は、同じX/Z列の読み込み済み範囲で下から最初の空間へ移し、1個のアイテムへの変換を再試行します。元の範囲外位置は移動しますが、種類・数量は保持します。安全な復元位置がない場合は保存を保護して停止します。
- 投下処理の予算待ちでも範囲外の位置を保持しないように修正。投下に失敗した落下物は保持し、20tickごとに再試行します。期限切れ状態を若返らせてブロックとして再配置しません。
- 水で固まったコンクリートも落下物として読み込めます。
- 復元が拒否された場合は、対象行と理由を `Bridge falling restore rejected:` としてログに出します。全復元が成功するまで、地形の規則・通常流体の更新を開始しません。

独立検証60件は成功しています。追加したUEの保存・復元テスト、修正後のWindows UEビルドと実再開はこの環境では未実行です。再度停止した場合は `UEBridge.log` の `Bridge falling restore rejected:` 行で原因を特定できます。
